HTTP log ingestion, queuing, storage and metrics

Architecture

Logs enter through POST /logs, are validated per entry, pushed onto a bounded raw_logs channel and processed by the worker pool (enrichment, then service routing). The publisher delivers each enriched log to RabbitMQ, falling back to a bounded in-memory buffer while disconnected. Per-destination consumers acknowledge only after the batch writer stores the log in SQLite, rotating dead letters when retries are exhausted. One metrics registry records counters on the ingestion path and serves GET /metrics and this page.

Package responsibilities

internal/config

Environment and file settings, parsed and validated with documented defaults.

Bounded raw-logs queue and the enrichment/routing worker pool.

internal/enrich

Timestamp, IP, environment and hostname enrichment.

internal/router

Config-driven service-to-destination routing with defaults.

internal/queue

RabbitMQ publisher, reconnect backoff, fallback and consumers.

internal/storage

SQLite batch writer, retries, dead letters and replay.

internal/metrics

Single source of truth for counters, snapshots and backlog.

internal/dashboard
